# M14 — Sandbox, editor, modding, 1.0

## Delivered
- **Sandbox options:** a desert slider (arid maps), the Nile flood, a building style (Italy, north, east, Egypt) and a random-map button, on top of the M8 sandbox (map size, coast, river, hills, forest, marsh, difficulty).
- **Map files:** `save_map`/`load_map` store a painted map (`.urbsmap`: terrain, height, groundwater, fertility, resources, roads, variants; zstd). A scenario can use `"map_file"` instead of a generated map.
- **Scenario editor** (Main menu → Scenario editor):
  - Generate a starting map, then paint terrain, raise and lower land, place resources, roads and bridges, or erase.
  - Set the mission level, era, region, entry side, start hour, treasury, starting goods, gods, trade partners and goals.
  - Saves to `<user data>/scenarios/<name>/` (scenario.json, map.urbsmap and a script.lua template to edit by hand). "Save and play" starts it at once.
- **Custom scenarios** (Main menu → Custom scenarios): lists scenarios from the user folder and from enabled mods, to play or edit.
- **Mod loader:**
  - Main menu → Mods lists mods in `mods/` next to the game data and in the user data folder. Enable, reorder, Apply.
  - Mods merge into the base definitions by `id`; a broken mod is reported by file and entry and switched off, not half-loaded.
  - `urbs_headless --mod <dir>` (repeatable) for testing.
  - `mods/example_vintners_guild/` ships as a working example: a new good, recipe, building, trade partner and scenario.
- **Modding guide:** `docs/10-modding.md`.
- **Accessibility:** the existing UI scale setting, plus a colour-blind option that switches overlays from green–red to an orange–grey–blue scale.
- **Release:**
  - Version 1.0.0 comes from CMake (`URBS_VERSION`) and is shown on the main menu and by `urbs_headless --version`.
  - `.github/workflows/release.yml` builds, tests and packages macOS, Windows and Linux archives when a `v*` tag is pushed.
  - `tools/package/package_macos.sh` now ships the `mods/` folder.
- **CI:** the push workflow skips the long tests (campaign and stress); the release workflow runs everything. The stress step used a `--perf-check` flag that the runner never had and silently ignored. It now checks that the shortened stress run makes no allocations in the tick.

## Exit check
- **Local:** all tests pass on macOS (Apple M1), including the 14 gated campaign missions and the save-compatibility, map-file and mod tests.
- **Bot results:** the bot wins 28 of 32 runs across the campaign (see M13).
- **Release:** v1.0.0 is tagged locally. The GitHub release for all three platforms needs the repository pushed and the tag published, which triggers the release workflow. Windows and Linux builds come only from that workflow. They have not been built or run yet.

## Retro
- **Bot as playtester:** the autoplay bot was the most useful tool of the project. Most balance bugs and simulation bugs (lost errand roles, unsold pottery, cut-off sites) surfaced as the bot failing a mission. Multi-seed evaluation was essential, because a single run is too chaotic to judge a change.
- **Stale binaries:** evaluation scripts don't build. Twice a failed build silently re-ran the old binary. Always check the build before trusting results.
- **Flags:** unknown command-line flags are ignored by `urbs_headless`. That hid the dead CI check. Consider rejecting unknown flags.
- **Still open:**
  - audio (none yet);
  - custom sprites in mods;
  - a human playtest of missions 13 and 15, which the bot wins only on some seeds;
  - notarized macOS builds.
